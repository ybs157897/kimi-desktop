# 专家团

专家团把多个专业子 Agent 组织成一棵固定的协作树：主 Agent 把任务交给团长，团长再按职责委派成员，核验结果后统一回复。它适合代码审查、架构设计、产品研究等需要多个视角但又需要单一交付口径的任务。

专家团由 Kimi Code Desktop 管理并保存在本地，不读取或依赖 WorkBuddy 等其他应用的配置。每个专家团同时是一个标准 Kimi Plugin，包含 Agent 文件和一个用于启动团队的 Agent Skill。

## 通过对话创建

在 Desktop 中打开「设置」→「专家团」，选择「对话创建」。应用会打开一个新会话并预填 `/expert-manager`。你也可以直接在新会话中输入：

```
/expert-manager 创建一个代码审查专家团，分别检查正确性、安全性和可维护性
```

`expert-manager` 会依次确认团队目标、团长、成员职责、工具权限和颜色。确认最终结构后，它才会生成本地专家包。适合先用自然语言描述需求，再由 Kimi 补齐角色提示词。

创建时请让角色保持互补：团长只负责拆解、委派、核验和汇总；成员负责一个清晰领域。除非成员必须修改文件，否则使用「只读」工具权限。

## 手动创建

选择「手动创建」可以直接填写完整配置：

1. 输入专家团标识、显示名称、描述和颜色。标识只能包含小写字母、数字和连字符。
2. 配置团长的名称、职责和系统提示词。团长会自动获得 `Agent` 和 `AgentSwarm` 工具，并且只能委派给当前团队成员。
3. 添加至少一个成员 Agent，为每个成员选择「只读」或「完整」工具权限。
4. 可选填写快捷提示词，保存后生成专家包。

普通成员默认是叶子 Agent，不会继续派发其他 Agent。「只读」适合调研、审查和分析；「完整」额外允许编辑文件和运行 Shell 命令。

## 使用专家团

保存后，列表会显示团队的启动命令。例如标识为 `code-review` 的专家团对应：

```
/expert-code-review 审查当前未提交变更
```

命令先激活团队 Skill，再将完整任务交给团长。团长调用成员 Agent，并把去重、核验后的结果返回主 Agent。你也可以在对话中自然地说「让代码审查专家团检查当前改动」，主 Agent 会根据 Skill 描述决定是否激活。

关闭专家团后，运行时会停止加载其 Agent 和启动 Skill；重新开启即可恢复。编辑会重新生成并热加载整个专家包。删除操作会先卸载 Plugin，再把本地专家包移到系统废纸篓。

## 本地文件

专家团源文件位于：

```text
$KIMI_CODE_HOME/experts/<team-id>/
├── expert-team.json
├── kimi.plugin.json
├── agents/
└── skills/
```

默认的 `$KIMI_CODE_HOME` 是 `~/.kimi-code`。`expert-team.json` 是 Desktop 编辑器的数据源，`kimi.plugin.json`、`agents/` 和 `skills/` 是 Kimi 运行时读取的标准 Plugin 内容。

::: warning 注意
系统提示词和完整工具权限会直接影响 Agent 的行为。导入或手工修改专家包后，应在启用前检查每个角色的提示词与工具范围。
:::

附着模式连接到外部 kap-server 时，Desktop 只能编辑和保存专家包，不会替外部服务安装 Plugin。需要在外部宿主中安装 `$KIMI_CODE_HOME/experts/<team-id>`，再按该宿主的方式重新加载或重启；在此之前，对话创建和即时启停会保持不可用。

## 专家团提示词建议

一份稳定的团长提示词应明确以下内容：

- 如何判断任务范围，以及何时向用户补充提问。
- 哪类任务交给哪个成员，成员之间是否可以并行。
- 如何验证成员结论、处理冲突和删除重复发现。
- 最终输出的结构、优先级和完成标准。

成员提示词应聚焦一个领域，并要求最后一条消息成为完整、可独立理解的交付结果。需要更细的 Agent 字段和权限说明时，阅读 [Agent 与子 Agent](./agents.md#自定义-agent)。
