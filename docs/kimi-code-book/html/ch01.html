第 1 章 总览与架构

本章回答三个问题：Kimi Code 是什么、monorepo 如何组织、以及贯穿全部实现的设计主线是什么。

#1.1 Kimi Code 是什么

Kimi Code 是 Moonshot AI（月之暗面）出品的终端 AI 编码代理，命令名 kimi。它在终端里运行，能够读改代码、执行 shell 命令、搜索文件、抓取网页，并基于反馈决定下一步。开箱即用 Moonshot 的 Kimi 模型，也支持其他兼容供应商。

与前一本书的主角（Grok Build，纯 Rust）不同，Kimi Code 是一个 TypeScript / pnpm monorepo（约 20 个 workspace 包、40 万行 TS），技术选型上有几个鲜明的产品决策：

  • 单二进制分发：用 Node.js 官方 SEA（Single Executable Application） + postject 打包，把 node-pty 等原生 .node 资产内嵌进二进制，一条命令安装、毫秒级启动 TUI。
  • 自研 TUI 渲染库：pi-tui，不用 ink/react，是一个"免依赖的终端图形栈"，为聊天界面高频流式更新量身定做。
  • 双引擎架构：agent-core（v1）与 agent-core-v2（DI × Scope 新架构）同仓并存，v2 已是默认引擎，KIMI_CODE_LEGACY_FLAG=1 可回退。
  • 多宿主复用：CLI（TUI）、VSCode 扩展（内嵌 SDK）、Web（kap-server）——"一个 SDK、三种宿主"。

#1.1.1 运行形态

形态 触发方式 引擎
交互式 TUI kimi v2（默认）/ v1（legacy flag）
非交互 kimi -p "..." v2 原生 print runner

#1.3 总体架构：壳-引擎严格分层

┌──────────────────────────────────────────────────────────────┐
│ apps/kimi-code（CLI/TUI 外壳）                                  │
│  参数解析 + 进程生命周期 + 终端 UI + 更新/迁移/反馈              │
│  ★ 不直接 import agent-core（AGENTS.md 硬约束）                 │
└──────────────────────────┬───────────────────────────────────┘
                           │ 唯一入口：@moonshot-ai/kimi-code-sdk
                           │ （KimiHarness / Session 门面）
┌──────────────────────────▼───────────────────────────────────┐
│ packages/node-sdk（SDK）                                       │
│  v1: createKimiHarness() → SDKRpcClient（进程内 RPC）          │
│  v2: createKimiHarnessV2() → bootstrap() + klient memory 传输 │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│ packages/agent-core-v2（引擎）    packages/agent-core（v1）    │
│  DI × Scope 四层作用域树           Agent/Session 门面 + RPC    │
│  App/Workspace/Session/Agent       （v2 的前传，WIP port 源）  │
└──────────────────────────┬───────────────────────────────────┘
                           │
      ┌────────────────────┼────────────────────┐
      ▼                    ▼                    ▼
 kap-server（REST/WS）  klient（客户端 SDK）  acp-server（ACP 适配）
      │                    │                    │
 apps/kimi-inspect     apps/vscode（内嵌）    IDE/宿主 ACP 客户端

三条架构主线：

  1. 壳-引擎分层极干净：CLI/TUI 不碰引擎，一切能力经 SDK 门面；v1→v2 引擎切换只改一个工厂函数（createKimiHarnessV2）+ 一个环境变量（KIMI_CODE_LEGACY_FLAG），TUI 层对引擎版本无感知。
  2. 作用域即架构（v2）：App → Workspace → Session → Agent 四层 LifecycleScope 作用域树是 v2 的第一公民——资源拥有者决定生命周期，所有能力都是可挂账本、可撤回、可内省的 DI 单元。kap-server 甚至直接反射整个 DI 注册表做 RPC（"注册的服务就是公共契约"）。
  3. 一切可重放状态走 wire journal：每 Agent 一个 wire.jsonl 追加日志 + 纯函数 Op/Model，undo、压缩、续会话、崩溃恢复全部是对日志的确定性重放。这是两代引擎共享的持久化哲学。
